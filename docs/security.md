# Security notes

- The stream URLs, and any tokens or passwords in them, grant live access to the cameras. Store them only in `/etc/camwall/camwall.conf` (root:root, 0600), never in the script, the unit, the shell profile or this repository. The `.gitignore` excludes `camwall.conf` and `*.env`. At runtime, systemd passes them through the service environment to camwalld, which expands the `<NAME>` templates and passes the URLs to the wall in its environment. camwalld's configuration errors name the variable, never its value. The plane wall (the default) reads the URLs from its environment and never puts them in a command line. The GStreamer fallback includes each URL in an ffmpeg command-line argument; visibility of those to other users depends on the system's process-access permissions, so the config file's permissions alone do not protect them.
- With the GStreamer fallback, `systemctl status camwall` and `ps` print the ffmpeg command lines, tokens included. Do not paste that output anywhere. ffmpeg and libav log levels above `error` print the stream URLs as well; both walls log at `error`.
- If a token or password has been pasted anywhere (chat, tickets, shell history), change it on the camera or recorder (in UniFi Protect, regenerate the token) and update the config file.
- The service runs as an unprivileged account that is only in the `video`, `render` and `i2c` groups.
- The unit is sandboxed: no new privileges and an empty capability set, a read-only filesystem except its own state and runtime directories (`ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`), no access to kernel tunables, modules, logs, control groups or the clock, and network sockets limited to IPv4, IPv6, Unix and netlink. `systemd-analyze security camwall` reports the result; the exposure level of the unit file alone went from 9.0 to 3.4 in an offline check. Device access (DRM, V4L2, media, DMA heaps, i2c) is not restricted yet. The plane wall's nodes are mapped (see [Design](design.md#the-plane-wall)); restricting them is in [TODO](../TODO.md). `ProtectProc=invisible` stops the service from seeing other users' processes. It does not hide the service's own processes from other users.
- With the GStreamer fallback, to keep the tokens out of other users' `ps` output you would have to mount `/proc` with `hidepid=2` on the whole system, which affects every login session and is not done by `install.sh`. This was not tried on the reference Pi.
- RTSPS connections do not verify the server certificate (this ffmpeg build rejects `-tls_verify` for RTSP input), and plain RTSP is not encrypted at all, including any password in it. This is intentional: camwall is meant for an internal, protected network, so do not use it across an untrusted one.
- Nothing here needs SSH or admin access on the cameras or recorder; with UniFi, do not enable SSH on the gateway for this project.
