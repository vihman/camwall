# Security notes

- The tokens grant live access to the cameras. Store them only in `/etc/camwall/camwall.conf` (root:root, 0600), never in the script, the unit, the shell profile or this repository. The `.gitignore` excludes `camwall.conf` and `*.env`. At runtime, systemd passes them through the service environment and the script includes each token in an ffmpeg command-line argument. Visibility to other users depends on the system's process-access permissions; the config file's permissions alone do not protect these runtime copies. The decode-to-plane program reads the tokens from its environment and never puts them in argv.
- `systemctl status camwall` and `ps` print the ffmpeg command lines, tokens included. Do not paste that output anywhere. ffmpeg log levels above `error` print the stream URLs as well.
- If a token has been pasted anywhere (chat, tickets, shell history), regenerate it in Protect and update the config file.
- The service runs as an unprivileged account that is only in the `video`, `render` and `i2c` groups.
- The unit is sandboxed: no new privileges and an empty capability set, a read-only filesystem except its own state and runtime directories (`ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`), no access to kernel tunables, modules, logs, control groups or the clock, and network sockets limited to IPv4, IPv6, Unix and netlink. `systemd-analyze security camwall` reports the result; the exposure level of the unit file alone went from 9.0 to 3.4 in an offline check. Device access (DRM, V4L2, DMA heaps, i2c) is not restricted yet because the exact set of nodes the decoder path needs has not been mapped on the Pi. `ProtectProc=invisible` stops the service from seeing other users' processes. It does not hide the service's own processes from other users.
- To keep the tokens out of other users' `ps` output you would have to mount `/proc` with `hidepid=2` on the whole system, which affects every login session and is not done by `install.sh`. This was not tried on the reference Pi.
- The RTSPS connection does not verify the gateway certificate (this ffmpeg build rejects `-tls_verify` for RTSP input). This is intentional: camwall is meant for an internal, protected network, so do not use it across an untrusted one.
- Do not enable SSH on the UniFi gateway for this project; nothing here needs it.
